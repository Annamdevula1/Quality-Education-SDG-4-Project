Project Overview

EduAI is a complete, professional AI-powered academic early warning system that combines Machine Learning (Random Forest) and IBM Granite Generative AI (via IBM watsonx.ai) to help educators identify students who may need academic support — before they fall significantly behind. The system is built entirely on synthetic data; no real student information is used anywhere.

System Pipeline (End-to-End)

1
Synthetic Data Generation
500 student records across 3 performance segments. Fully reproducible with seed=42. No personally identifiable information (PII).
2
Data Validation & Processing
Missing value imputation (median fill), duplicate removal, out-of-range clipping [0–100], and full descriptive statistics report.
3
Risk Label Creation
Deterministic rule-based labelling using fully documented, transparent thresholds. Fully auditable logic.
4
Exploratory Data Analysis (8 Charts)
Marks, attendance, quiz, assignment distributions; scatter plots (prev vs current marks, attendance vs marks); correlation heatmap (lower triangle — bug fixed); risk distribution bar and pie charts.
5–6
Random Forest Training & Evaluation
200 estimators, balanced class weight, 80/20 stratified split. Achieved 97.0% accuracy. Confusion matrix and feature importance charts saved to outputs/evaluation/.
7
Transparent Risk Factor Identification
5 rule-based observable indicators identified separately from the ML model. Clear thresholds documented and displayed to educators.
8
Individual Student Analysis Engine
Combines ML prediction + risk factors + IBM Granite response into one structured result per student.
9
Demonstration Students
6 predefined synthetic students (2 per risk level) for live system demonstration without requiring real student data.
10
Model Persistence
Trained model and label encoder saved via joblib to outputs/model/. Loaded automatically on app startup if files are present.
11–14
IBM Granite Integration
Structured prompt sent to IBM Granite via watsonx.ai. Parsed response returns explanation + 3 recommendations + monitoring suggestion. Falls back to clearly labelled Demo Mode if credentials are absent.
15–20
Streamlit Professional Dashboard
6 pages: Dashboard, Student Analysis, Demo Students, Student Results (CSV export), EDA Charts, About. Fully integrated end-to-end.

Bug Fixes Applied in This Updated Version

BUG FIXED Correlation heatmap mask variable never applied
eda.py — line 134 — plot_correlation_heatmap()

Problem: The mask variable was computed (upper-triangle) but never passed to sns.heatmap(). A full symmetric heatmap was always rendered despite the comment saying "show lower triangle".
Fix: Added mask=mask as a parameter to the sns.heatmap() call. The heatmap now correctly shows only the lower triangle.

BUG FIXED Dead variable and import statement inside a for-loop
train.py — lines 94–95 — main() Step 7 loop

Problem: pred = metrics["model"] was assigned but immediately discarded. from ml_model import predict_single was placed inside the loop and re-executed on every iteration.
Fix: Removed the dead pred variable. Moved the predict_single import to the top-level import block in train.py.

BUG FIXED Deferred import placed inside a cached Streamlit function
app.py — line 266 — bootstrap()

Problem: from ml_model import train_model, evaluate_model was placed inside the @st.cache_resource function instead of at the top of the file. This was inconsistent with all other imports in the project.
Fix: Moved both imports to the top-level import block at the start of app.py.

BUG FIXED Wrong function name referenced in error message
ml_model.py — line 201 — load_model()

Problem: The FileNotFoundError message said "Run train_and_save() first" — but this function does not exist in the codebase. The correct public function is train_evaluate_save().
Fix: Corrected the message to "Run train_evaluate_save() first (or run train.py)."

Ethical Principles

  • Synthetic data only — no real student personally identifiable information (PII) used anywhere
  • Transparent, rule-based risk factors with fully documented thresholds
  • AI supports educators — all final decisions rest with teachers, not the system
  • No assumptions about personal, medical, family, financial or social circumstances
  • IBM Granite credentials managed via environment variables only — never hard-coded
  • Risk labels are explicitly not permanent — communicated clearly throughout the UI
  • Demo mode responses are clearly labelled "DEMO — Not IBM Granite" in every view
  • No medical or psychological diagnoses made by any component of the system
